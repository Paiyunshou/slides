02

系统目的与四层架构

输入 → 派生 → 汇总 → 归档，财务只看结果、数据可追溯

FOUR LAYERS

各出口主体（J002、1000_1A00 等）输入申报表、关单表、征免表三张原始数据，系统按四层自动加工，最终在集团汇总表沉淀历史底账，并驱动「通知财务入账」「保存底账」两条自动流程。

关键设计 · KEY DESIGN

三表关联键（各表唯一）

申报表出口货物报关单号→关单表21 位关单号
征免表报关单号→关单表21 位关单号
1000 征免表海关报关单单号→1000 申报表出口报关单号

三表通过关单号互相查询：判定某张出口关单是否已申报退税 / 已做征税或免税申报，并取回对应金额。

为什么按年拆表

多维表单表上限 5 万行，关单 / 申报数据逐年增长，必须按年拆表才能稳定运行。

· J002：数据量大 → 申报、关单、征免、汇总均按年建表（-2026、-2027…）

· 1000_1A00：生产型企业、数据量小 → 不拆年，长期单表

· 跨年申报期：上年关单最晚次年 3 月完成申报，次年表需能查入上年关单的申报数据

给维护者的一句话

你只需要把三张输入表的原始数据贴进去，其余统计、通知、归档全部由公式和工作流自动完成——不要手工改汇总表和集团汇总表。

03

核心公式与自动流程

公式负责判定和取数，工作流负责通知和归档

FORMULAS

全部在飞书多维表内配置，不写代码。三张输入表更新后，公式自动重算，工作流按状态变化自动触发。

判申报状态 关单表

判断每一张出口关单最终走了哪条申报路径：退税、征税还是免税。

申报表 有记录 → “退税申报”
征免表有记录 且 征免=征税 → “征税申报”
征免表有记录 且 征免=免税 → “免税申报”
其他情形 → 空（未申报）

月申报年月 关单表

取回这张关单实际申报的属期，用来判断是否已申报、是否逾期。

申报表 有记录 → 反馈该条申报的申报年月
征免表 有记录 → 反馈征免申报年月
都无记录 → 空

汇汇总聚合 汇总表

按 公司 × 属期 × 申报批次，把该批次下所有关单金额动态加总。

申报人民币 / 美元离岸价
申报退税额 · 申报征退税差
销项税额

03

飞书自动通知财务，附申报征退税差、销项税额金额与批次消息带按钮直达「征退税差明细 / 销项税额明细」只读视图，财务点进去即可核对、复制、导出

02

工作流按 公司名称 × 申报属期 × 申报批次 到集团汇总表查重1000 无批次，按 公司 × 属期 查

03

没有 → 新增一条底账；已有 → 只覆盖有差异的申报数据，不产生重复记录集团汇总表纯历史归档、不用公式，与动态数据分离

维护总原则

改数据只改三张输入表；改结构先复制上年表再改引用；集团汇总表永远不手改、只由「保存底账」写入。
